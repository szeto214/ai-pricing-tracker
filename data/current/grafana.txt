FAQ
What is an active AI user?
An active AI user is anyone who uses Grafana Assistant during the monthly billing period — sending a message, clicking an action like Explain in Assistant, or working with Assistant through any of its surfaces: in Grafana or Workspace, in Slack or Microsoft Teams, in the Grafana mobile or desktop app, or through the gcx CLI. Connecting through the Cloud MCP server also counts as active use. Running an Assistant Automation manually, or having one run automatically, also counts as active use.
Each active user includes up to 40M tokens per month. Additional usage is charged at $2 per 1M tokens. Token limits apply per user and are not shared across users.
What consumes my tokens?
Token consumption falls into two buckets:
Your per-user tokens (40M per user per month) cover everything you do with Assistant manually — conversations in any surface, Assistant Search, dashboard and query generation, investigations you start, and any prompts or questions you send within a system-initiated investigation. A manual Assistant Automation run counts toward the token usage of the user who starts it. Scheduled and event-triggered runs count toward the creator’s token usage.
The system-initiated pool (25M per month on Free and Pro; custom pools on contracted plans) covers all other AI work that runs automatically — investigations triggered by alerts, incidents, or IRM webhooks, LLM-based evals and guards from Agent Observability, and service-account or API usage.
Watcher agents are free while in public preview.
Once a pool is used, additional tokens are billed at $2 per 1M.
What is the system-initiated usage?
Tokens consumed by system-initiated AI activity — investigations triggered automatically by alerts, incidents, watchers or IRM webhooks, LLM-based evals and guards, and service-account or API usage — draw from a shared monthly pool: 25M tokens on Free and Pro plans, with custom pool sizes on contracted plans, separate from per-user allowances. The pool is shared across all system-initiated AI usage in your organization. Assistant Automations are the exception: scheduled and event-triggered runs draw from their creator’s per-user tokens, not this pool. (This pool replaces the 25M tokens previously described as “service account usage.”)
Does using gcx or the Grafana MCP server consume my tokens?
Not for data access. When your own coding agent or MCP client uses gcx or the Cloud MCP server to query Grafana — pulling metrics, dashboards, alerts, or incidents — the reasoning happens in your agent’s model, and no Grafana AI tokens are consumed. Grafana tokens are consumed when Grafana’s models do the work: chatting with Assistant through the gcx CLI, invoking Assistant tools like ask_assistant through MCP, or starting an investigation from either surface. One thing to know: connecting through the Cloud MCP server counts you as an active AI user for that billing period, even if your token usage is zero.
Does Assistant Search consume my tokens?
Searching itself doesn’t. The retrieval — semantic and keyword search across your dashboards, incidents, investigations, alert rules, and infrastructure — runs on Grafana’s search index, not an AI model, and consumes no tokens. Tokens are consumed by the AI work around a search: a small amount to rewrite your query for better results, and — the bulk of it — when Assistant reasons over what comes back, either as part of its reply in chat or through Deep Search’s enrichment, which runs a full Assistant pass on each new search. There is no separate search-token pool; this usage draws from the same allowances as the rest of Assistant.
What is an AI token?
A token is a piece of text that an AI model reads or generates. Tokens can be whole words, parts of words, punctuation, or spaces. As a rough rule of thumb: 1 token ≈ 4 characters in English; 100 tokens ≈ 75 words. Tokens can be consumed by active AI users and by system-initiated usage; system-initiated usage is not billed per user.

FAQ
What is a test execution?
A test execution is a Synthetic test running in a probe location per minute of run time.
Example: A synthetic test running in 5 locations that takes 1.5 minutes to complete will consume 10 executions each time it runs.
How do I estimate the number of test executions?
To estimate the number of test executions per month, you will need the following inputs:
Number of Locations (Probes)
Number of Targets (Tests)
Duration of Test (rounded to the nearest minute)
Frequency of Tests (in Minutes)
Using the above info, you can calculate the number of test executions per month by applying this formula (where 43,200 is the total minutes in a month):
probes x tests x duration x (43,200 / frequency)

What are MultiHTTP checks and k6 scripted checks?
MultiHTTP checks are like HTTP checks but you can test multiple URLs in a single check to validate multi-step user flows.
k6 scripted checks are like MultiHTTP checks, but you can write the checks in code instead of via a form-based approach.
How do I estimate the number of test executions?
To estimate the number of test executions per month, you will need the following inputs:
Number of Locations (Probes)
Number of Targets (Tests)
Duration of Test (rounded to the nearest minute)
Frequency of Tests (in Minutes)
Using the above info, you can calculate the number of test executions per month by applying this formula:
# of locations (probes) X number of targets (tests) X duration of test (rounded up to the nearest minute) X [43,200 total minutes in a month / frequency of tests in minutes)

What is a virtual user hour (VUh)?
VUh is calculated by using the following formula:
(Maximum number of VUs x test execution duration in minutes) / 60 minutes = VUh
If your test ramps up to a maximum of 100 VUs and runs for 10 minutes, the test run will use 16.67 VUh ((100 VUs x 10 minutes)/60 = 16.67 VUh).
Note that VU hours are calculated based on the period that the test run executes, not the preconfigured test duration. If the test duration is 2 or more hours but runs for only 30.01 minutes, then the subscription will be charged for the test-execution period rounded up to the next minute (in this case, 31 minutes).
